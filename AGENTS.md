# Image Compressor — инженерный вход

Локальная утилита для пакетного сжатия и преобразования изображений. Ценность — получить читаемый результат с предсказуемыми параметрами, не потеряв исходники и прежние результаты. Входы: JPEG, PNG, WebP, HEIF/HEIC, AVIF; выходы: JPEG, WebP, HEIF/HEIC, AVIF (PNG только вход). Доступность кодека проверяется фактически, не по наличию имени в списке. Принятый прикладной контракт — [Application API v1](docs/architecture/application-api.md); авторские проверки, независимый ACCEPT после ремонта R1/R2 и точные ограничения — в [verification](docs/verification/command-first-refactoring.md). Это не EXE-релиз и не квалификация всех платформ.

## Архитектурный курс и границы

- Сначала независимый прикладной API: команды/запросы, типизированные результаты и ошибки, единый владелец правил и файловых эффектов. CLI, GUI и MCP — адаптеры, не отдельные реализации компрессора.
- Ядро не импортирует Qt, CLI-парсер или MCP SDK, не вызывает `input()`, не печатает диагностические сообщения в машинный stdout. Прямой вызов API должен работать без окна.
- Выбирать минимально достаточную архитектуру по реальным гарантиям. Очередь, daemon, IPC, Command Bus, БД, workflow и MCP заранее не требуются. Oracle обосновывает профиль и границы.
- Command-first-срез и отдельный [FigCraft → PySide6 эксперимент](docs/figcraft_gui_experiment/REPORT.md) независимо приняты в своих границах. Настоящий дизайн в `design/` и opt-in `gui_pyside6_v2/` сохранены поверх неизменённого публичного API; это не замена GUI по умолчанию и не EXE-релиз. Старые `gui/`, `gui_main.py`, ядро и PFK snapshot не менять в рамках эксперимента; PySide и PyQt проверять в отдельных средах/процессах. MCP-сервер продукта и destructive mode не входят. Технический/визуальный ACCEPT не квалифицирует все платформы, DPI или физические OS-dialog/drop; новые изменения требуют отдельного поручения.
- Только create-only публикация проверенного staging через atomic no-replace hard link с final readback; сохранять исходники и прежние результаты. `delete_original=True` явно отвергается до эффектов, а не игнорируется. Общий контракт и tests владеют коллизиями/кооперативной отменой; trusted local namespace не означает sandbox или crash durability.

## Рабочий цикл и команда

1. Проверить корень, ветку, фактические изменения; найти владельца и потребителей символа. Сохранить чужую работу. До существенной записи определить область и наблюдаемые критерии.
2. Oracle планирует → Coder реализует и проверяет → независимый Reviewer принимает. Hermes после оформления основы — тонкий оркестратор, не второй разработчик/проверяющий.
3. Роли Pi раздельны: [oracle](.pi/agents/oracle.md) — `openai-codex/gpt-6-astra`, `xhigh`; [coder](.pi/agents/coder.md) и [reviewer](.pi/agents/reviewer.md) — `openai-codex/gpt-6.1-sol`, `max`. Сохранять отдельные беседы; замечания возвращать тому же автору, проблемы архитектуры — тому же Oracle. Нельзя молча менять модель/поставщика. Реально наблюдённый уровень рассуждения отличать от запрошенного.
4. Один писатель на пересекающиеся файлы. До ACCEPT кандидат и index заморожены; Reviewer пишет только свой отчёт/probes, не исправляет проверяемый код. После ACCEPT тот же Reviewer завершает затронутые docs/instructions и разрешённое selective сохранение/доставку по [рабочему циклу](docs/instructions/development.md). Новая source/test неисправность возвращается тому же Coder; closeout не новая независимая приёмка. Один связный обзор, без проверяющего проверяющего.
5. Существенные решения, запуски и отказы кратко фиксировать в [LOG.md](LOG.md); локальные сырые сессии/результаты — в игнорируемом `.agent-work/`. Долговечное знание принадлежит `docs/`, не только чату.
6. До завершения обновить относящиеся контракты, архитектуру, команды/примеры и ограничения; проверки должны пройти через настоящий вход с повторным открытием результата. План, написанный тест, exit процесса и независимое принятие — разные факты.

## Полномочия и сохранность

Разрешены чтение/изменение этого проекта, создание отдельных веток, изолированные зависимости разработки и тесты на синтетических данных в пределах поручения. Не читать `.env`, credentials, личные изображения/архивы, чужие журналы/БД. Не менять глобальные настройки Pi/Hermes или другие проекты. `tools/project-foundation/` — полная сохранённая редакция пакета; не редактировать её при обычной разработке. Репозиторий-источник пакета также только для чтения.

Ветки этой работы: `docs/project-foundation` для подготовки, затем `refactor/command-first` для реализации. Основа перешла как незакоммиченные изменения, не отдельный docs-коммит. По прямому поручению пользователя accepting Reviewer после ACCEPT владеет docs closeout, selective stage/commit принятого среза и branch-only push в существующий `origin` этого проекта на `refs/heads/refactor/command-first` с exact SHA readback. Coder/Oracle index/commit/push не получают; новых разрешений перед каждым принятым срезом не требуется. Merge/tag/release/force/переписывание истории, новый remote и изменение visibility не разрешены. Не применять `reset`, `clean`, `stash`, массовый `add` или обход защит ради чистого дерева; private outputs/sessions/venvs/cache/build/dist не публиковать.

Фактическая исходная среда и правила запуска — в [тестировании](docs/instructions/testing.md). Непроверенные новые команды нельзя называть работающими. Итог — полезное изменение, настоящие проверки/NOT RUN, ветка/сохранение и конкретный обязательный остаток. Когда исходная цель выполнена, остановиться.
