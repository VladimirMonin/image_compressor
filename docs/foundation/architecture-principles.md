# Ответственность прежде каркаса

Направление зависимостей: оболочка → прикладной сценарий → преобразование и файловая инфраструктура. Ядро не зависит от PyQt6, argparse/другого CLI-парсера, MCP SDK, окон или терминального ввода. Команда — явное намерение выполнить действие, не обязательно класс или shell-строка. Запрос состояния не должен исполнять преобразование.

Один владелец определяет допустимые параметры, доступность кодеков, раскрытие файлов/каталогов, дедупликацию и порядок, выходные имена, коллизии, публикацию и судьбу исходника. Адаптеры используют этот путь, а не создают собственные варианты. Чистые операции расчёта размеров и параметры отделяются от файловых эффектов там, где это уменьшает риск и делает проверку понятнее; интерфейс на каждую функцию не требуется.

## Текущее и целевое

Исходная база `7707849` содержит `classes.py` (Pillow и интерактивный запуск), `gui/worker.py` (Qt, именование, цикл, удаление), `gui/utils.py` (свой поиск файлов). Это найденная реализация, а не целевой API. Она допускает опасные совпадения входа/выхода и не должна автоматически стать контрактом сохранности.

По [плану Oracle](../plans/command-first-refactoring.md) реализован и независимо принят профиль A: синхронный прикладной сервис с локальными callback/token, без jobs/IPC/БД. Фактические owners, операции и типы — [Application API v1](../architecture/application-api.md); история авторских проверок, NEEDS_CHANGES, ремонта и независимого ACCEPT — [verification](../verification/command-first-refactoring.md). Учебные статьи PFK не являются спецификацией проекта.

## Контракт и эффекты

До реализации закрепить входы/единицы/defaults, наблюдаемый результат, ошибки, частичный исход и допустимые эффекты. Качество, формат и размеры валидируются и при прямом API-вызове. Поддержка кодека определяется реальной возможностью чтения/записи. Выходные пути — данные, не исполняемая строка.

Файл считается опубликованным только в определённой точке; неуспех до неё сохраняет прежние данные. Нужна явная политика совпадения с источником, существующего результата, двух входов с одним выходом и изменений условий между подготовкой и записью. Create-only публикация: уникальный staging рядом с target → полная проверка → атомарный no-replace `os.link` → final readback. Удаление/замена источников отвергаются; hard-link unsupported не даёт unsafe fallback. Очистка удаляет только собственный учтённый временный файл и пустой собственный dir. Нельзя объяснить повреждение оригинала тем, что адаптер «не так вызвал» общедоступный API.

Отмена/прогресс принадлежат прикладному исполнению, а не Qt-флагу как единственному источнику истины. Различаются запрос остановки и реально прекращённая работа. Синхронной утилите не нужны Job ID, реестр задач или сохранение сессии. Выбран trusted local namespace, не sandbox от враждебной подмены каталогов; stat/fstat guards и atomic visibility не crash durability. Cooperative cancel может допустить уже прошедший checkpoint link и ждёт возврата native codec. Job/workspace/recovery или более сильный барьер — новые требования и пересмотр профиля, не бесплатный флаг.

## Оболочки и совместимость

CLI разбирает аргументы и сериализует общий результат; stdout машинного режима не содержит диагностических строк. Существующие `ImageCompressor` и worker используют общий API как совместимые адаптеры. Они не сохраняют вторую копию правил. Небезопасная старая семантика не имеет приоритета над сохранностью.

В этой работе не меняются дизайн, раскладка и виджеты. Минимальное переподключение существующего worker/поиска к API допускается, если оно нужно для единственного владельца. Оно проверяется в своей границе без заявления о новой визуальной приёмке. MCP и новый GUI описываются как будущие потребители, не как реализованные функции.

Общая библиотека не означает общую живую сессию между процессами. Attached-режим, общий несохранённый workspace, IPC, долговечная очередь и восстановление после сбоя требуют новых требований и решения о владельце состояния.

## Проверка и пересмотр

Проверять прямой вызов без GUI, реальный CLI → API → доступный кодек → файл → повторное открытие, существенные отказы и сохранность. Если сохранён совместимый потребитель — проверить и его соединённый путь. Наличие классов и правильный JSON без результата этого не доказывают.

Пересмотр нужен при новом реальном адаптере, другой модели состояния, новой гарантии публикации/отмены либо доказанной цене существующей границы. Основания: [философия](project-philosophy.md), [тесты](testing-strategy.md), [разработка](../instructions/development.md).
