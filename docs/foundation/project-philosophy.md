# Зачем существует проект

Image Compressor локально сжимает и преобразует отдельные изображения и наборы файлов; при необходимости уменьшает размеры, сохраняя пропорции. Пользователь получает пригодные для дальнейшего использования файлы и понятный итог обработки. Автоматизация и будущие оболочки должны пользоваться теми же правилами, что и человек.

Существующие приложение на PyQt6 и класс `ImageCompressor` подключены к общему прикладному API; command-first-срез независимо принят в заявленной границе. CLI служит первым автоматизируемым адаптером. Это принятый архитектурный переход, не разработка нового графического интерфейса. Отдельно принят [эксперимент FigCraft → PySide6](../figcraft_gui_experiment/REPORT.md) на неизменённом API с сохранением старого окна; opt-in GUI остаётся инженерным экспериментом, не заменой default GUI. MCP, сервер и долговечные задачи остаются вне области.

## Приоритеты при конфликте

1. Сохранность исходников и чужих результатов; отсутствие молчаливого удаления/перезаписи.
2. Честный исход операции: успех, ошибка и частичный результат различаются; готовый файл проверяется повторным чтением.
3. Одни правила преобразования, валидации, выбора имён и публикации для всех оболочек.
4. Понятный контракт, простая структура и воспроизводимая локальная работа без Qt в ядре.
5. Производительность после корректности. Параллелизм оправдан реальным выигрышем и не отменяет порядок эффектов/сохранность.

Поддержка формата — работающий доступный кодек, а не имя в выпадающем списке. Входы — JPEG, PNG, WebP, HEIF/HEIC и AVIF; выходы — JPEG, WebP, HEIF/HEIC, AVIF. PNG только вход. Возможности/ограничения принятой реализации закреплены в [прикладном контракте](../architecture/application-api.md) и [фактических проверках среды](../verification/command-first-refactoring.md), не в списке импортированных плагинов. Целевой размер файла и отсутствие потерь для сжатия с потерями не обещаются.

## Инженерные принципы

**Работающий результат важнее количества документов.** План Oracle полезен, когда следующий кодер может выполнить его без угадывания существенной политики. Документация не заменяет реальную конвертацию и независимую проверку.

**Command-first не означает shell-first.** Операция выражает намерение через API. Парсер аргументов, Qt-сигналы и будущие MCP-вызовы переводят запрос/результат, а не определяют продуктовые правила. GUI не обязан запускать CLI подпроцессом.

**Простота важнее демонстрации шаблонов.** Выбираем наименьший профиль, выполняющий текущие гарантии. Не добавляем реестр команд, шину, очередь, IPC, БД, сохранение задач или обработчик процессов только ради возможного будущего клиента. Переход к другим гарантиям оформляется отдельно, без обещания «никогда больше не переписывать».

**Проверка соразмерна цене ошибки.** Переименование документа проверяется адресно; путь удаления/публикации требует проверки байтов и сохранности при отказе. Тесты проходят настоящего владельца, а не вторую реализацию компрессора в тестах.

**Знание имеет одного владельца.** Контракт поведения, правила тестирования и диагностики живут в своих документах/коде. История объясняет причину, не отменяет действующие инструкции. Требования, найденная реализация, предложение и выполненный результат отмечаются раздельно. Дата документа не подтверждает работоспособность.

**Завершение конечно.** Oracle → кодер → независимый проверяющий; обязательные замечания возвращаются тому же автору. После выполненных критериев заканчиваем заказанную задачу, не начинаем соседнюю переработку экранов или бессрочный аудит.

## Сохранность и границы

В этой поставке исходники и существующие результаты сохраняются всегда: только создание нового проверенного файла, без overwrite и удаления. `delete_original=True` явно отвергается до эффектов, включая старый GUI-worker. Исправление старой небезопасной семантики — документированное изменение поведения, не скрытая совместимость. Возвращение разрушительных режимов требует отдельного разрешения и защищённого протокола последствий; это не deferred обязательство этой работы.

Проверки выполняются на синтетических изображениях в собственных временных папках. Никакой загрузки изображений в облако, внешней аналитики или публикации из факта использования пакета философии не следует.
